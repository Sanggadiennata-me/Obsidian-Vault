## Pengertian Aksesibilitas Web (A11y)

Aksesibilitas Web (sering disingkat **A11y**, merujuk pada huruf 'A' diikuti 11 huruf hingga 'y') adalah prinsip perancangan situs web agar dapat digunakan secara setara dan mudah oleh semua orang tanpa terkecuali, termasuk penyandang disabilitas:

- Penyandang tunanetra yang mengandalkan perangkat lunak pembaca layar (*screen reader* seperti NVDA, JAWS, atau VoiceOver).
- Pengguna dengan disabilitas motorik fisik yang mengoperasikan web hanya menggunakan papan ketik (*keyboard*) tanpa mouse.
- Pengguna tunarungu yang membutuhkan teks terjemahan (*closed captions*) pada video.
- Pengguna dengan gangguan penglihatan warna (*color blindness*) atau lansia dengan penglihatan terbatas.

Membangun web yang aksesibel bukan sekadar kepatuhan etika, tetapi juga standar hukum internasional dan sangat menguntungkan SEO mesin pencari.

## Prinsip Dasar WCAG (POUR)

Standar aksesibilitas web dunia dirumuskan oleh W3C dalam dokumen **WCAG (Web Content Accessibility Guidelines)**, yang bertumpu pada 4 prinsip utama (POUR):

1. **Perceivable (Dapat Dirasakan)**: Informasi dan antarmuka pengguna harus dapat disajikan dengan cara yang dapat dirasakan oleh pancaindra pengguna (misalnya teks alternatif `alt` untuk gambar).
2. **Operable (Dapat Dioperasikan)**: Seluruh komponen antarmuka harus dapat dikendalikan sepenuhnya melalui keyboard saja tanpa jebakan fokus.
3. **Understandable (Dapat Dipahami)**: Konten dan instruksi navigasi harus jelas, mudah dibaca, dan konsisten.
4. **Robust (Kokoh & Kompatibel)**: Kode HTML harus valid dan dapat diinterpretasikan secara andal oleh beragam browser dan teknologi asistif (*assistive technologies*).

## Aturan Emas: Semantik Alami vs ARIA

**WAI-ARIA (*Accessible Rich Internet Applications*)** adalah spesifikasi atribut HTML tambahan untuk meningkatkan aksesibilitas komponen antarmuka yang kompleks.

Namun, terdapat aturan pertama ARIA dari W3C yang sangat terkenal:
> *"No ARIA is better than Bad ARIA."* (Tidak menggunakan ARIA jauh lebih baik daripada menggunakan ARIA yang salah).

Jika sebuah elemen HTML bawaan telah memiliki semantik dan fungsi yang Anda butuhkan (seperti `<button>`, `<a>`, `<nav>`, `<input>`), **selalu gunakan elemen HTML asli tersebut!** 

Jangan membuat tombol palsu dari elemen `<div>`:

```html
<!-- BURUK: Membutuhkan banyak konfigurasi rumit agar aksesibel -->
<div class="tombol" onclick="bukaMenu()" role="button" tabindex="0">
  Buka Menu
</div>

<!-- BAIK: Secara alami sudah mendukung klik, fokus tab, spasi, dan enter -->
<button type="button" onclick="bukaMenu()">
  Buka Menu
</button>
```

## Kapan ARIA Benar-Benar Dibutuhkan?

Atribut ARIA digunakan ketika Anda membangun komponen antarmuka tingkat lanjut (seperti tab panel interaktif, menu dropdown kustom, atau dialog kustom) yang tidak memiliki representasi tag bawaan di HTML dasar.

Berikut adalah atribut-atribut ARIA yang paling sering digunakan:

### 1. `aria-label`
Memberikan label teks yang tidak tampak di layar visual, khusus dibacakan untuk pengguna pembaca layar. Sangat tepat untuk tombol yang hanya berupa ikon visual:

```html
<!-- Tanpa aria-label, pembaca layar hanya mendengar "button, x" yang membingungkan -->
<button type="button" aria-label="Tutup jendela modal">
  <span aria-hidden="true">&times;</span>
</button>
```

### 2. `aria-hidden="true"`
Menyembunyikan elemen grafis atau ornamen dekoratif murni dari pembaca layar agar tidak menimbulkan kebisingan audio yang tidak perlu bagi tuna netra:

```html
<button type="button">
  <svg aria-hidden="true" width="16" height="16"><!-- Ikon Keranjang --></svg>
  Tambah ke Keranjang
</button>
```

### 3. `aria-expanded`
Memberi tahu pembaca layar apakah menu dropdown atau akordion terkait sedang dalam keadaan terbuka (`true`) atau tertutup (`false`):

```html
<button type="button" aria-expanded="false" aria-controls="menu-dropdown">
  Menu Navigasi
</button>
<div id="menu-dropdown" hidden>
  <!-- Daftar tautan menu -->
</div>
```

### 4. `aria-labelledby` dan `aria-describedby`
Menghubungkan elemen kontrol dengan teks judul atau teks bantuan penjelasan di bagian lain dokumen menggunakan referensi ID:

```html
<input type="password" id="pass" aria-describedby="petunjuk-pass">
<p id="petunjuk-pass">Kata sandi harus terdiri dari minimal 8 karakter dan mengandung 1 angka.</p>
```

### 5. `role="alert"` (Live Region)
Memberi tahu pembaca layar untuk segera menyuarakan pesan penting atau notifikasi kesalahan tanpa harus menunggu pengguna berpindah fokus:

```html
<div role="alert" class="pesan-error">
  Email atau kata sandi yang Anda masukkan salah.
</div>
```

## Navigasi Keyboard dan Atribut `tabindex`

Pengguna tanpa mouse bernavigasi melompat antar elemen interaktif menggunakan tombol <kbd>Tab</kbd> pada keyboard.

Secara default, elemen interaktif asli seperti `<a>`, `<button>`, `<input>`, dan `<select>` sudah otomatis masuk ke dalam antrean navigasi tab.

Jika diperlukan penyesuaian khusus, Anda dapat mengontrol perilaku fokus menggunakan atribut `tabindex`:

| Nilai Atribut | Perilaku Navigasi Keyboard | Rekomendasi Kasus |
| :--- | :--- | :--- |
| `tabindex="0"` | Memasukkan elemen ke dalam urutan tab keyboard alami sesuai posisinya di dokumen. | Komponen kustom non-standar yang perlu menerima fokus keyboard. |
| `tabindex="-1"` | Elemen **tidak dapat dijangkau** via tombol Tab, tetapi dapat difokuskan secara terprogram via JavaScript (`element.focus()`). | Jendela modal saat dibuka, atau kontainer pesan kesalahan untuk mengalihkan perhatian fokus. |
| `tabindex="1+"` (Angka Positif) | **Sangat dilarang!** Memaksa urutan tab meloncat melompati elemen lain. | Merusak alur navigasi alami bagi pengguna disabilitas. |
