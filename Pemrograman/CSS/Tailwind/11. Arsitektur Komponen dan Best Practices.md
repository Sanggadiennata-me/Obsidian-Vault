#programming 

Saat proyek web bertambah besar, tantangan utama dalam menggunakan utility-first adalah menjaga agar deretan class tetap teratur dan menghindari duplikasi kode yang melelahkan. Di tingkat mahir, pengembang menggunakan strategi arsitektur komponen modern.

---

## 1. Tiga Pendekatan Mengelola Duplikasi Komponen

### A. Ekstraksi Komponen Template (Pendekatan Terbaik)
Jika Anda menggunakan framework JavaScript berbasis komponen (seperti React, Vue, Svelte) atau template engine backend (seperti Laravel Blade atau Astro), **jangan pernah menduplikasi class secara manual**. Bungkus class tersebut ke dalam komponen mandiri:

```jsx
// Button.jsx (Komponen Reusable di React)
export function Button({ variant = 'primary', children, ...props }) {
  const baseStyle = "px-5 py-2.5 rounded-xl font-semibold text-sm transition transform active:scale-95";
  const variants = {
    primary: "bg-blue-600 hover:bg-blue-700 text-white shadow-md shadow-blue-500/20",
    secondary: "bg-slate-100 hover:bg-slate-200 text-slate-700",
    danger: "bg-rose-600 hover:bg-rose-700 text-white",
  };

  return (
    <button className={`${baseStyle} ${variants[variant]}`} {...props}>
      {children}
    </button>
  );
}
```
Dengan cara ini, jika Anda ingin mengubah warna seluruh tombol di website, Anda hanya perlu mengedit satu berkas `Button.jsx`.

### B. Menggunakan Direktif `@apply` (Gunakan Secara Bijak)
Jika proyek Anda hanya menggunakan berkas HTML biasa tanpa framework komponen, Anda dapat menggunakan direktif `@apply` di dalam berkas CSS input:

```css
/* src/input.css */
@layer components {
  .btn-primary {
    @apply px-4 py-2 bg-blue-600 hover:bg-blue-700 text-white font-semibold rounded-lg shadow transition;
  }
}
```

> **Peringatan Penting Tim Inti Tailwind**:
> Jangan tergoda untuk mengubah semua hal menjadi class `@apply` seperti `.card`, `.hero`, `.sidebar`. Jika semua class diabstraksi kembali ke CSS biasa, Anda akan kehilangan seluruh manfaat utility-first dan kembali ke masalah klasik penamaan class dan ukuran CSS membengkak.

### C. Menggunakan Pustaka Penggabung Class (`clsx` + `tailwind-merge`)
Pada aplikasi React atau Next.js skala besar, class dinamis sering kali bertabrakan jika dipadukan dengan props dari luar. Gunakan fungsi pembantu `cn`:

```bash
npm install clsx tailwind-merge
```

```ts
// lib/utils.ts
import { clsx, type ClassValue } from "clsx";
import { twMerge } from "tailwind-merge";

export function cn(...inputs: ClassValue[]) {
  return twMerge(clsx(inputs));
}
```

Fungsi `cn()` otomatis menyelesaikan konflik class, misalnya jika komponen memiliki default `p-4` lalu pengguna mengirim props `p-6`, maka `p-6` yang akan menang secara bersih.

## 2. Urutan Standar Penulisan Class (*Class Ordering*)

Menulis class secara acak membuat markup sulit dibaca. Ikuti urutan anatomi standar dari luar ke dalam:

1. **Posisi & Tampilan**: `relative`, `absolute`, `flex`, `grid`, `hidden`, `block`.
2. **Dimensi Ukuran**: `w-full`, `max-w-md`, `h-16`.
3. **Jarak Luar & Dalam**: `m-4`, `mx-auto`, `p-6`, `gap-4`.
4. **Tipografi**: `text-xl`, `font-bold`, `text-center`, `tracking-tight`.
5. **Warna Background & Garis**: `bg-white`, `border`, `border-slate-200`.
6. **Bentuk & Bayangan**: `rounded-2xl`, `shadow-lg`, `overflow-hidden`.
7. **Interaksi & Transisi**: `transition`, `transform`, `hover:scale-105`.
8. **Modifier Responsif & Dark Mode**: `md:flex`, `lg:w-1/3`, `dark:bg-slate-900`.
