## Mengapa Penanganan Eror Sangat Krusial?

Sebaik apa pun kode yang kita tulis, aplikasi di dunia nyata pasti akan menghadapi situasi kesalahan (*error/exceptions*):
- Pengguna memasukkan data dengan format yang salah.
- Sambungan internet tiba-tiba terputus di tengah jalan saat memuat data.
- Berkas yang dicari di server ternyata telah dihapus atau dipindahkan.

Jika sebuah eror terjadi dan tidak ditangani dengan baik (*unhandled exception*), **seluruh jalannya program JavaScript akan terhenti seketika (*crash*)**, layar pengguna menjadi putih beku, dan aplikasi tidak dapat digunakan lagi.

Untuk mencegah malapetaka tersebut, JavaScript menyediakan mekanisme **Penanganan Eror (*Error Handling*)** menggunakan struktur `try - catch - finally` dan kata kunci `throw`.

## 1. Mengenal Jenis-Jenis Eror Bawaan JavaScript

Ketika sebuah eror terjadi, mesin JavaScript akan membangkitkan objek bawaan bertipe `Error`. Objek ini memiliki 3 properti utama:
- `name`: Nama klasifikasi eror (misal: `"TypeError"`).
- `message`: Kalimat penjelasan penyebab eror.
- `stack`: Jejak riwayat berkas dan nomor baris tempat terjadinya eror (*stack trace*).

Beberapa jenis eror bawaan yang paling sering ditemui:

| Tipe Eror | Penyebab Terjadinya | Contoh Kode Pemicu |
| :--- | :--- | :--- |
| **ReferenceError** | Memanggil variabel yang belum pernah dideklarasikan. | `console.log(variabelGhaib);` |
| **TypeError** | Melakukan operasi yang tidak sesuai dengan tipe datanya. | `const x = 10; x();` (Angka dipanggil sebagai fungsi) |
| **SyntaxError** | Menuliskan tata bahasa kode JavaScript yang salah. | `let nama = ;` (Kurang tanda nilai) |
| **RangeError** | Memberikan nilai angka di luar batas rentang yang diizinkan. | `new Array(-5);` (Panjang array negatif) |

## 2. Membangkitkan Eror Sendiri: Kata Kunci `throw`

Anda tidak perlu menunggu sistem memicu eror secara alami. Anda dapat membangkitkan sinyal eksepsi secara sengaja menggunakan kata kunci `throw` ketika aturan logika bisnis aplikasi Anda dilanggar.

Format standar yang dianjurkan adalah membangkitkan instans dari objek `Error`:

```javascript
function prosesTransaksi(hargaBarang, uangDibayar) {
  if (uangDibayar < hargaBarang) {
    // Membangkitkan eror secara sengaja
    throw new Error(`Uang pembayaran kurang! Kurang Rp ${hargaBarang - uangDibayar}`);
  }

  const kembalian = uangDibayar - hargaBarang;
  return `Transaksi berhasil! Uang kembalian: Rp ${kembalian}`;
}
```

## 3. Struktur Penangkap Eror: `try - catch - finally`

Untuk menangani eror secara anggun (*graceful error handling*) tanpa membuat aplikasi crash, bungkus kode berisiko di dalam blok `try`:

```javascript
try {
  console.log("1. Memulai proses transaksi...");
  
  // Mencoba memanggil fungsi dengan uang yang kurang
  const res = prosesTransaksi(100000, 75000);
  console.log(res); // Baris ini dilewati jika terjadi throw
  
} catch (error) {
  // Blok catch HANYA dieksekusi jika terjadi eror di dalam blok try
  console.error("2. Terjadi kesalahan pada transaksi!");
  console.error(`Pesan Error: ${error.message}`);
  
} finally {
  // Blok finally PASTI dieksekusi 100%, baik ada eror maupun sukses tanpa eror
  console.log("3. Menutup koneksi mesin kasir (Pembersihan Selesai).");
}

console.log("4. Program terus berjalan normal ke baris berikutnya tanpa crash!");
```

### Peran Krusial Blok `finally`:
Blok `finally` adalah tempat terbaik untuk melakukan operasi pembersihan sumber daya (*cleanup*), seperti:
- Menutup koneksi database atau soket jaringan.
- Mematikan animasi loading spinner di antarmuka web, terlepas dari apakah proses unduh data sukses atau gagal.

## 4. Membedakan Penanganan Berdasarkan Jenis Eror (`instanceof`)

Terkadang kita ingin memberikan penanganan berbeda tergantung jenis masalah yang terjadi. Gunakan operator `instanceof` untuk memeriksa kelas dari objek eror yang ditangkap:

```javascript
try {
  // Potensi terjadinya TypeError atau ReferenceError
  jalankanProses();
} catch (error) {
  if (error instanceof TypeError) {
    console.warn("Kesalahan tipe data terdeteksi:", error.message);
  } else if (error instanceof ReferenceError) {
    console.warn("Variabel tidak ditemukan:", error.message);
  } else {
    // Jika eror tidak kita kenali, lempar kembali keluar (Re-throw)
    console.error("Eror kritis tak terduga!");
    throw error;
  }
}
```
