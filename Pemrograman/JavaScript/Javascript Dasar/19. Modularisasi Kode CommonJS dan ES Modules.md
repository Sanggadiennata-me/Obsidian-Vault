## Mengapa Kita Membutuhkan Modularisasi?

Ketika pertama kali belajar pemrograman, kita terbiasa menuliskan seluruh baris kode di dalam satu berkas tunggal (misalnya `app.js`). Namun saat aplikasi berkembang menjadi ribuan baris dengan puluhan fitur berbeda, menulis semuanya di satu tempat akan menimbulkan masalah besar:

- Berkas menjadi terlalu panjang dan sangat sulit dipahami (*monolithic spaghetti code*).
- Variabel dan fungsi rawan bertabrakan nama (*global scope collision*).
- Kolaborasi tim menjadi kacau karena semua programmer menyunting berkas yang sama.

Solusi dari tantangan di atas adalah **Modularisasi (*Modularization*)**, yaitu seni memecah kode program yang besar menjadi berkas-berkas terpisah yang lebih kecil, mandiri, dan memiliki fungsi spesifik (*Single Responsibility Principle*). Berkas-berkas terpisah ini disebut sebagai **Modul**.

![Konsep Modularisasi](img/Modularisasi.png)

## Dua Sistem Modul dalam Ekosistem JavaScript

Dalam sejarah perkembangannya, terdapat dua sistem modularisasi utama:
1. **CommonJS (CJS)**: Standar tradisional yang digunakan oleh Node.js sejak awal kemunculannya.
2. **ES Modules (ESM)**: Standar resmi internasional yang ditetapkan oleh ECMA International sejak ES6 (2015), dan saat ini menjadi standar masa depan di browser maupun Node.js.

## 1. Sistem Tradisional Node.js: CommonJS (CJS)

CommonJS menggunakan fungsi `require()` untuk mengimpor dan objek `module.exports` untuk mengekspor:

```javascript
// Berkas: matematika.js
function tambah(a, b) {
  return a + b;
}

function kurang(a, b) {
  return a - b;
}

// Mengekspor fungsi
module.exports = { tambah, kurang };
```

```javascript
// Berkas: app.js
// Mengimpor dari berkas matematika.js
const { tambah, kurang } = require('./matematika.js');

console.log(tambah(10, 5)); // Output: 15
```

## 2. Standar Resmi Modern: ES Modules (ESM)

ES Modules adalah standar resmi JavaScript modern yang menggunakan kata kunci `export` dan `import`.

### a. Named Export dan Named Import
Digunakan saat satu modul memiliki **beberapa variabel atau fungsi** yang ingin diekspor:

```javascript
// Berkas: utils.mjs
export const namaAplikasi = "Nusantara App";

export function hitungLuas(p, l) {
  return p * l;
}

export function hitungKeliling(p, l) {
  return 2 * (p + l);
}
```

Cara mengimpor fungsi-fungsi tersebut:
```javascript
// Berkas: main.mjs
import { namaAplikasi, hitungLuas } from './utils.mjs';

console.log(namaAplikasi); // Output: Nusantara App
console.log(hitungLuas(10, 4)); // Output: 40
```

#### Memberikan Nama Alias (Renaming with `as`):
Jika nama fungsi yang diimpor bertabrakan dengan nama variabel di berkas lokal, gunakan kata kunci `as`:

![Alias Import](img/alias.png)

```javascript
import { hitungLuas as luasPersegi } from './utils.mjs';

console.log(luasPersegi(5, 5)); // Output: 25
```

#### Mengimpor Seluruh Modul Sekaligus (`import *`):
```javascript
import * as Rumus from './utils.mjs';

console.log(Rumus.namaAplikasi);
console.log(Rumus.hitungLuas(8, 2));
```

### b. Default Export dan Default Import
Digunakan jika sebuah berkas modul dirancang untuk **mengeksport satu entitas utama saja** (misalnya sebuah class atau satu fungsi inti). Hanya boleh ada **satu `export default` per berkas**:

```javascript
// Berkas: Pengguna.mjs
export default class Pengguna {
  constructor(nama) {
    this.nama = nama;
  }
  
  sapa() {
    console.log(`Halo, nama saya ${this.nama}`);
  }
}
```

Saat mengimpor *Default Export*, Anda **tidak perlu menggunakan tanda kurung kurawal `{}`**, dan Anda bebas memberi nama variabel apa pun:

```javascript
// Berkas: main.mjs
import UserClass from './Pengguna.mjs';

const user1 = new UserClass("Siti");
user1.sapa(); // Output: Halo, nama saya Siti
```

## Cara Mengaktifkan ES Modules di Lingkungan Node.js

Secara default, versi Node.js lawas memperlakukan berkas `.js` sebagai CommonJS. Terdapat dua cara untuk mengaktifkan fitur ES Modules modern di Node.js:

### Cara 1: Menggunakan Ekstensi Berkas `.mjs`
Cukup ubah ekstensi berkas JavaScript Anda dari `.js` menjadi `.mjs` (*Module JavaScript*). Node.js akan otomatis mengeksekusinya sebagai ES Module.

### Cara 2: Menambahkan `"type": "module"` di `package.json`
Jika proyek Anda memiliki banyak berkas, menambahkan konfigurasi pada tingkat proyek adalah cara terbaik:
1. Buka terminal proyek dan ketik `npm init -y` untuk membuat berkas `package.json`.
2. Tambahkan baris konfigurasi `"type": "module"`:

```json
{
  "name": "belajar-js-dasar",
  "version": "1.0.0",
  "type": "module"
}
```

![Konfigurasi package.json](img/package.json.png)

Dengan pengaturan ini, seluruh berkas berekstensi `.js` di dalam proyek akan dieksekusi sebagai ES Modules secara default.

## Menggunakan ES Modules di Peramban Web (Browser)

Browser modern mendukung ES Modules secara natif tanpa memerlukan alat *bundler* tambahan.

Cukup tambahkan atribut `type="module"` pada tag `<script>` dokumen HTML Anda:

```html
<!DOCTYPE html>
<html lang="id">
<head>
  <meta charset="UTF-8">
  <title>Belajar ES Modules di Browser</title>
</head>
<body>
  <h1>Aplikasi Berbasis ES Modules</h1>

  <!-- Memuat berkas JavaScript sebagai modul -->
  <script type="module" src="main.js"></script>
  
  <!-- Fallback untuk peramban kuno yang belum mendukung modul -->
  <script nomodule src="bundle-fallback.js"></script>
</body>
</html>
```

Karakteristik skrip dengan `type="module"` di browser:
- Otomatis bersifat `defer` (diunduh di latar belakang tanpa memblokir rendering HTML).
- Otomatis berjalan dalam mode ketat (*Strict Mode*).
- Setiap variabel yang dideklarasikan di dalam modul tidak akan bocor ke jendela global `window`.
