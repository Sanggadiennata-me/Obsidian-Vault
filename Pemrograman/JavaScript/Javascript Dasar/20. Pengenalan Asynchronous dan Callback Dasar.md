## Paradigma Asinkron (Asynchronous JavaScript)

Secara bawaan alamiah, JavaScript adalah bahasa yang bersifat **Single-Threaded** (hanya memiliki satu utas jalur eksekusi pada satu waktu) dan berjalan secara **Sinkron (*Synchronous*)**.

Artinya, JavaScript mengeksekusi instruksi secara berurutan baris demi baris dari atas ke bawah. Satu baris instruksi harus selesai terlebih dahulu sebelum baris berikutnya dapat dimulai (*Blocking Process*).

```
[Instruksi 1]  ---> Selesai
[Instruksi 2]  ---> Menunggu... Selesai
[Instruksi 3]  ---> Menunggu... Selesai
```

## Masalah dengan Pendekatan Sinkron (Blocking)

Bayangkan sebuah aplikasi kasir kafe:
- Jika kasir bekerja secara **Sinkron (Blocking)**: Saat pelanggan memesan kopi yang membutuhkan waktu seduh 5 menit, kasir akan berdiri diam menunggu kopi tersebut selesai dibuat sebelum melayani antrean pelanggan berikutnya. Seluruh antrean pelanggan di belakangnya akan tertahan dan membeku selama 5 menit!
- Jika kasir bekerja secara **Asinkron (Non-Blocking)**: Kasir mencatat pesanan pelanggan pertama, memberikan nomor antrean atau bel panggil (*pager*), lalu langsung menyapa dan melayani pelanggan kedua tanpa menunggu kopi selesai diseduh. Saat kopi pertama sudah selesai, bel panggil berbunyi dan pelanggan pertama mengambil kopinya.

Dalam pemrograman web, tugas-tugas berat seperti mengambil data dari server internet (*API Request*), membaca berkas besar dari hard disk, atau menunggu klik tombol dari pengguna tidak boleh dijalankan secara sinkron karena akan membuat antarmuka browser membeku (*freeze*).

## 1. Simulasi Proses Asinkron dengan `setTimeout`

Untuk mensimulasikan tugas yang membutuhkan waktu jeda di latar belakang, JavaScript menyediakan fungsi global `setTimeout`:

```javascript
// Sintaks: setTimeout(callbackFunction, delayDalamMilidetik);

console.log("1. Memulai pesanan.");

// Menunda eksekusi selama 3000 milidetik (3 detik)
setTimeout(() => {
  console.log("2. Pesanan selesai dibuat setelah 3 detik.");
}, 3000);

console.log("3. Kasir melanjutkan melayani pelanggan berikutnya.");
```

Tampilan urutan eksekusi di terminal:
```text
1. Memulai pesanan.
3. Kasir melanjutkan melayani pelanggan berikutnya.
2. Pesanan selesai dibuat setelah 3 detik.
```

Perhatikan bahwa baris instruksi ke-3 dieksekusi **sebelum** baris instruksi ke-2! Mesin JavaScript tidak memblokir jalannya program sembari menunggu timer 3 detik selesai di latar belakang.

### Mengapa `setTimeout` dengan Waktu `0` Milidetik Tetap Dijalankan Belakangan?
Perhatikan cuplikan teka-teki terkenal berikut:
```javascript
console.log("A");

setTimeout(() => {
  console.log("B");
}, 0);

console.log("C");
```
Meskipun timer diatur ke `0` milidetik, hasil cetakannya tetaplah: **`A -> C -> B`**!

Mengapa hal ini terjadi?
Hal ini karena arsitektur **Event Loop** di JavaScript:
1. Perintah sinkron (`"A"` dan `"C"`) langsung masuk dan dieksekusi di tumpukan utama (*Call Stack*).
2. Perintah `setTimeout` didelegasikan ke penangan latar belakang (*Web APIs / Libuv*).
3. Setelah timer selesai, fungsi callback dimasukkan ke dalam antrean tunggu (*Callback Queue*).
4. **Event Loop** hanya akan mengambil fungsi dari *Callback Queue* dan menjalankannya ke *Call Stack* **setelah seluruh baris kode sinkron utama selesai bersih 100%**.

## 2. Pola Penanganan Asinkron Klasik: Callback Function

Bagaimana kita mengolah data hasil dari operasi asinkron jika datanya baru tersedia beberapa detik kemudian?

Pola tertua dan paling mendasar di JavaScript adalah menggunakan **Callback Function**, yaitu meneruskan fungsi sebagai argumen yang akan dipanggil saat tugas asinkron selesai:

```javascript
function buatKopi(namaPesanan, panggilPelanggan) {
  console.log(`Pramusaji sedang meracik kopi ${namaPesanan}...`);

  setTimeout(() => {
    console.log(`Kopi ${namaPesanan} telah matang.`);
    // Memanggil fungsi callback dan mengirimkan hasil kopi
    panggilPelanggan(`Secangkir ${namaPesanan} Hangat`);
  }, 2000);
}

// Memanggil fungsi dengan mengirimkan callback
buatKopi("Espresso", (kopiJadi) => {
  console.log(`Pelanggan menerima: ${kopiJadi}. Nikmat sekali!`);
});
```

### Konvensi Node.js: Error-First Callback
Di ekosistem server Node.js, terdapat pola standar di mana parameter pertama pada fungsi callback selalu dialokasikan untuk objek `error`, dan parameter kedua untuk data hasil:

```javascript
function bacaDataSiswa(id, callback) {
  setTimeout(() => {
    if (id <= 0) {
      // Jika terjadi kesalahan, kirim objek error di parameter pertama
      callback(new Error("ID Siswa tidak valid!"), null);
      return;
    }

    // Jika sukses, kirim null untuk error, dan data di parameter kedua
    callback(null, { id: id, nama: "Budi Santoso" });
  }, 1000);
}

// Menjalankan Error-First Callback
bacaDataSiswa(1, (err, data) => {
  if (err) {
    console.error("Gagal membaca data:", err.message);
    return;
  }
  console.log("Data berhasil diterima:", data.nama);
});
```

## 3. Bahaya Callback Hell (Pyramid of Doom)

Pola callback sangat baik untuk satu atau dua operasi sederhana. Namun, masalah besar muncul ketika kita memiliki beberapa tugas asinkron berurutan yang saling bergantung satu sama lain (misalnya: Verifikasi akun &rarr; Ambil keranjang belanja &rarr; Proses pembayaran &rarr; Buat faktur &rarr; Kirim email):

```javascript
// CONTOH CALLBACK HELL (Piramida Kehancuran / Pyramid of Doom):
otentikasiUser(username, password, (err, user) => {
  if (!err) {
    ambilKeranjang(user.id, (err, cart) => {
      if (!err) {
        prosesPembayaran(cart.total, (err, payment) => {
          if (!err) {
            buatFaktur(payment.id, (err, invoice) => {
              if (!err) {
                kirimEmail(user.email, invoice, (err) => {
                  console.log("Transaksi selesai!");
                });
              }
            });
          }
        });
      }
    });
  }
});
```

Kode di atas membentuk segitiga miring ke kanan yang disebut **Callback Hell**. Kode menjadi sangat sulit dibaca, membingungkan saat mencari bug, dan sangat rapuh terhadap kesalahan penanganan eror.

Untuk menuntaskan masalah Callback Hell ini, standar JavaScript modern memperkenalkan **Promise** dan sintaks **Async/Await**, yang akan dipelajari secara mendalam pada kurikulum lanjutan (*JavaScript Advanced*).
